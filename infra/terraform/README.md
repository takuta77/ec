> The `.terraform.lock.hcl` was generated by OpenTofu and contains `registry.opentofu.org` provider hashes.

## 1. Bootstrap remote state (once, before first `tofu init`)

Create the S3 bucket and DynamoDB lock table. Choose names and record them — you will substitute them into `backend.tf` and the ecspresso configs.

```bash
REGION=ap-northeast-1
STATE_BUCKET=<your-bucket-name>      # e.g. myco-ec-api-tfstate
LOCK_TABLE=<your-lock-table-name>    # e.g. myco-ec-api-tflock

# Create S3 bucket (ap-northeast-1 requires LocationConstraint)
aws s3api create-bucket \
  --bucket "$STATE_BUCKET" \
  --region "$REGION" \
  --create-bucket-configuration LocationConstraint="$REGION"

# Enable versioning on the bucket
aws s3api put-bucket-versioning \
  --bucket "$STATE_BUCKET" \
  --versioning-configuration Status=Enabled

# Create DynamoDB lock table
aws dynamodb create-table \
  --table-name "$LOCK_TABLE" \
  --attribute-definitions AttributeName=LockID,AttributeType=S \
  --key-schema AttributeName=LockID,KeyType=HASH \
  --billing-mode PAY_PER_REQUEST \
  --region "$REGION"
```

After the resources exist, replace the placeholders in two places:

**`infra/terraform/backend.tf`** — replace both `REPLACE_ME_ec-api-tfstate` and `REPLACE_ME_ec-api-tflock`:
```hcl
terraform {
  backend "s3" {
    bucket         = "<your-bucket-name>"
    key            = "ec-api/terraform.tfstate"
    region         = "ap-northeast-1"
    dynamodb_table = "<your-lock-table-name>"
    encrypt        = true
  }
}
```

**`infra/ecspresso/*/ecspresso.yml`** (all four services) — replace `REPLACE_ME_ec-api-tfstate` in the `tfstate` plugin URL:
```yaml
plugins:
  - name: tfstate
    config:
      url: s3://<your-bucket-name>/ec-api/terraform.tfstate
```

## 2. Provision infrastructure

```bash
cd infra/terraform

tofu init          # downloads providers, configures S3 backend
tofu plan          # review changes
tofu apply         # provision all resources
```

Key resources created: VPC + subnets, ECS cluster, ALB, RDS (PostgreSQL), Amazon MQ (RabbitMQ), ECR repository, Secrets Manager secrets (empty — populate in step 3), IAM roles.

## 3. Populate secrets

After `tofu apply`, the Secrets Manager secrets exist but are empty. Populate each one with the real values.

Secret paths use the env-qualified prefix `ec-api/prod/<key>`.

```bash
# Database URL
aws secretsmanager put-secret-value \
  --secret-id ec-api/prod/database_url \
  --secret-string "postgresql+asyncpg://ec_admin:<password>@<rds-endpoint>:5432/ec"

# RabbitMQ URL (Amazon MQ broker uses AMQPS on port 5671)
aws secretsmanager put-secret-value \
  --secret-id ec-api/prod/rabbitmq_url \
  --secret-string "amqps://<user>:<password>@<mq-endpoint>:5671/"

# JWT private key (PEM file)
aws secretsmanager put-secret-value \
  --secret-id ec-api/prod/jwt_private_key \
  --secret-string file://path/to/jwt_private_key.pem

# JWT public key (PEM file)
aws secretsmanager put-secret-value \
  --secret-id ec-api/prod/jwt_public_key \
  --secret-string file://path/to/jwt_public_key.pem

# New Relic license key
aws secretsmanager put-secret-value \
  --secret-id ec-api/prod/new_relic_license_key \
  --secret-string "<new-relic-license-key>"
```

Retrieve endpoint values from tofu outputs if needed:
```bash
tofu -chdir=infra/terraform output
```

## 4. First image push + deploy

> This flow is normally automated in C-1b CD. Run manually for the initial deployment.

```bash
REGION=ap-northeast-1
ECR_URL=$(tofu -chdir=infra/terraform output -raw ecr_repository_url)
IMAGE_TAG=<git-sha-or-tag>   # e.g. abc1234

# Authenticate Docker to ECR
aws ecr get-login-password --region "$REGION" \
  | docker login --username AWS --password-stdin "$ECR_URL"

# Build and push the application image
docker build -t "$ECR_URL:$IMAGE_TAG" .
docker push "$ECR_URL:$IMAGE_TAG"

# Export variables required by ecspresso
export AWS_REGION="$REGION"
export IMAGE_TAG="$IMAGE_TAG"

# Run database migrations (one-off ECS task)
ecspresso run \
  --config infra/ecspresso/api/ecspresso.yml \
  --overrides '{"containerOverrides":[{"name":"app","command":["alembic","upgrade","head"]}]}'

# Deploy all four ECS services
for svc in api outbox-relay order-consumer checkout-sweeper; do
  ecspresso deploy --config "infra/ecspresso/$svc/ecspresso.yml"
done
```

## 6. Known boundaries (C-1a)

| Item | Status | Follow-up |
|------|--------|-----------|
| JWT key injection | Secrets Manager injects `JWT_PRIVATE_KEY` / `JWT_PUBLIC_KEY` as env vars, but the app currently reads `JWT_PRIVATE_KEY_PATH` (a file path) | Reconcile env-var vs path handling in **C-1c** |
| TLS / HTTPS | ALB is HTTP-only; no ACM certificate or Route 53 record provisioned | Add TLS termination + custom domain as follow-up |
| RDS availability | Single-AZ RDS instance (cost-optimised for initial rollout) | Promote to Multi-AZ in production follow-up |
| NAT Gateway | Single NAT Gateway (one AZ) | Add per-AZ NATs for HA in follow-up |
| Secret path convention | All secrets use env-qualified paths `ec-api/prod/<key>` | Consistent across environments; adjust prefix for staging/dev |
